## Schema set — `apps/mfr/lib/db/schema/`

Four domain files re-exported by `index.ts`, disjoint table names:

- `identity.ts` — Auth.js tables (`users`, `accounts`, `sessions`, `verification_tokens`) + `user_status` enum. Verbatim from `packages/auth/src/schema.ts`.
- `portal.ts` — `portal_*` tables. Verbatim from the former `apps/web/lib/db/schema.ts`.
- `reservations.ts` — `reservations`, `blocked_dates`, `booking_rules`, `activity_log` + `reservation_status` enum. Verbatim from `apps/reservations/lib/db/schema.ts`.
- `accounting.ts` — **NEW**, generated by `drizzle-kit pull` (introspection) against accounting prod, so it is byte-faithful: `"Shareholder"`/`"Transaction"`/`"LedgerEntry"`/`"TransactionApproval"`/`"Expense"`/`"ContributionGoal"`/`"AppSettings"`, `cuid` text PKs, enums (`TransactionType`/`ApprovalStatus`/`ExpenseCategory`), `numeric(12,2)`, `timestamp(3)`, all indexes + FKs. `_prisma_migrations` deliberately dropped (unified DB is push-managed). Timestamps use `mode: 'date'` (JS-side only; DDL unchanged) to match Prisma's `Date` returns and ease the Phase-3 port.

Config: `apps/mfr/drizzle.config.ts` → `schema/index.ts`, `dbCredentials.url = DIRECT_URL`, loads `.env.local` via dotenv. Runtime uses pooled `DATABASE_URL`; drizzle-kit uses unpooled `DIRECT_URL`.

## Push-only objects — `apps/mfr/lib/db/push-only.sql`

drizzle-kit push does NOT emit these; apply after each push to a fresh/reset
branch (`psql "$DIRECT_URL" -f lib/db/push-only.sql`). Verified that a normal
`drizzle-kit push` does **not** drop them:

- `btree_gist` extension
- `reservations_no_overlap` GiST EXCLUDE (no overlapping confirmed reservations)
- `booking_rules_singleton` CHECK (id = 1)
- `check_reservation_not_blocked()` / `check_blocked_date_not_reserved()` + their triggers
